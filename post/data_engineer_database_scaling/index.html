What

Note

あとで一つずつ深掘りするための索引。各キーワードは「どの課題を解く技術か」を一行で添えている。

🗄️ ストレージエンジンの基礎

キーワード ざっくり何を解く
B+ ツリー RDB の主流インデックス構造。範囲スキャンと点参照を両立させるための木。
LSM ツリー 書き込み偏重ワークロード向けの構造（Cassandra / RocksDB / BigTable 系）。WriteAmp / ReadAmp / SpaceAmp のトレードオフ。

🛡️ 耐久性・整合性

キーワード ざっくり何を解く
Write-Ahead Logging (WAL) 「先にログ、あとで本体」でクラッシュリカバリを保証する仕組み。
Two-Phase Commit (2PC) 複数ノードに跨るトランザクションの原子性を保つプロトコル。coordinator 障害で詰まる問題あり。
Three-Phase Commit (3PC) 2PC のブロッキング問題を緩和するための拡張。ネットワーク分断下の挙動が論点。

📈 可用性・スケールアウト

キーワード ざっくり何を解く
Read Replicas 読み込み負荷を水平分散する定番。レプリケーションラグと読み取り整合性がテーマ。
Leader-Follower Replication 書き込みは Leader、読み込みは Follower。フェイルオーバーと split-brain 対策。
Partitioning (Sharding) データ自体を分割して書き込みもスケールさせる。シャードキー設計とリバランスが肝。

⚡ 高速化・インデックス

キーワード ざっくり何を解く
Query Caching 結果 / プラン / ページの各レイヤでのキャッシュ。整合性とのトレードオフ。
Secondary Indexes 主キー以外の列で高速検索するためのインデックス。書き込みコストとのバランス。
Vector Indexes (FAISS, HNSW) 埋め込みベクトルの近傍探索。RAG / セマンティック検索の心臓部。
Materialized Views クエリ結果を物理化して読み取りを速くする。リフレッシュ戦略が論点。

🌐 分散処理

キーワード ざっくり何を解く
Distributed Joins シャード / ノードを跨ぐ JOIN の実行戦略（broadcast / shuffle / colocated）。

🔄 データフロー・イベント指向

キーワード ざっくり何を解く
Event Sourcing 「状態」ではなく「イベント列」を真実の源にする設計。監査性とリプレイ性が武器。
Change Data Capture (CDC) DB の変更を下流に流す仕組み。Debezium / BigQuery CDC / Datastream など。
