Mermaid Markdown Diagram Documentation

Why

README や設計ドキュメントで図を埋め込みたいとき、画像ファイルを生成して貼るのは面倒。 Mermaid なら Markdown のコードブロックとして書けて、GitHub / GitLab / Notion / Hugo などが標準でレンダリングしてくれる。差分も取りやすい。

What

  • Official https://mermaid.js.org/
  • Live Editor https://mermaid.live/edit
```mermaid
<diagramType>
    ...定義...
```

<diagramType> の部分で何の図を描くかが決まる。以下、よく使う / 知っておくと便利な図の種類をまとめる。

フローチャート (flowchart)

処理の流れ・分岐を表現する一番ベーシックな図。graph でも書けるが、新しい構文は flowchart。

flowchart LR
    A[開始] --> B{条件分岐}
    B -->|Yes| C[処理1]
    B -->|No| D[処理2]
    C --> E[終了]
    D --> E
  • 方向指定: TB (上→下) / BT / LR (左→右) / RL
  • ノード形状: [] 矩形 / () 角丸 / {} ひし形(条件) / (()) 円 / [[]] サブルーチン
  • 矢印: --> / --- (線のみ) / -.-> (点線) / ==> (太線)

シーケンス図 (sequenceDiagram)

API 呼び出しやプロトコルの 時系列を表現する。3-way handshake や OAuth フローを書くのに最適。

sequenceDiagram
    participant C as Client
    participant S as Server
    C->>S: SYN
    S->>C: SYN-ACK
    C->>S: ACK
    Note over C,S: Connection established
  • ->> 同期メッセージ / -->> 応答 / -x 失敗
  • Note over A,B: ... 注記
  • loop / alt / opt で繰り返し・分岐も書ける

ER 図 (erDiagram)

データベースのテーブル関係を可視化。BigQuery / RDBMS 問わずスキーマ設計の議論で使える。

erDiagram
    USER ||--o{ POST : writes
    USER {
        int id PK
        string name
        string email
    }
    POST ||--o{ COMMENT : has
    POST {
        int id PK
        string title
        text body
        int user_id FK
    }
    COMMENT {
        int id PK
        text body
        int post_id FK
    }
  • カーディナリティ記法
    • ||--|| 1対1
    • ||--o{ 1対多
    • }o--o{ 多対多
  • 属性に PK / FK を付けられる

クラス図 (classDiagram)

OOP のクラス設計。Go の interface 関係なども近似的に書ける。

classDiagram
    class Animal {
        +String name
        +int age
        +speak() void
    }
    class Dog {
        +String breed
        +bark() void
    }
    Animal <|-- Dog
  • <|-- 継承 / *-- コンポジション / o-- 集約 / --> 関連

ステート図 (stateDiagram-v2)

状態遷移。ワークフローエンジン (Argo / Airflow) のジョブ状態や、UI の画面遷移を書くのに便利。

stateDiagram-v2
    [*] --> Pending
    Pending --> Running: 実行開始
    Running --> Succeeded: 完了
    Running --> Failed: エラー
    Failed --> Running: リトライ
    Succeeded --> [*]
    Failed --> [*]
  • [*] が開始 / 終了
  • ネストした状態 (state X { ... }) も書ける

ガントチャート (gantt)

プロジェクトのスケジュール。マイルストーン管理。

gantt
    title リリーススケジュール
    dateFormat  YYYY-MM-DD
    section 設計
    要件定義           :a1, 2026-06-01, 7d
    基本設計           :a2, after a1, 10d
    section 実装
    バックエンド       :b1, after a2, 14d
    フロントエンド     :b2, after a2, 14d
    section テスト
    結合テスト         :c1, after b1, 7d

Git グラフ (gitGraph)

ブランチ戦略の説明やレビューで威力を発揮。

gitGraph
    commit id: "初回コミット"
    branch feature/login
    commit id: "ログイン画面実装"
    commit id: "バリデーション追加"
    checkout main
    merge feature/login id: "PR #1 マージ"
    branch feature/dashboard
    commit id: "ダッシュボード実装"
    checkout main
    merge feature/dashboard id: "PR #2 マージ"

円グラフ (pie)

比率の可視化。

pie title 工数配分
    "実装" : 45
    "レビュー" : 20
    "ミーティング" : 25
    "その他" : 10

C4 図 (C4Context)

ソフトウェアアーキテクチャ記述 (C4 model)。Context / Container / Component / Code の4階層。

C4Context
    title システム全体構成
    Person(user, "ユーザー")
    System(webapp, "Web アプリ")
    System_Ext(api, "外部 API")
    Rel(user, webapp, "利用")
    Rel(webapp, api, "呼び出し")

サンキー図 (sankey-beta)

フロー量の可視化。データ移動・予算配分。

sankey-beta
    Source A,Target X,10
    Source A,Target Y,5
    Source B,Target X,8

棒グラフ / 折れ線グラフ (xychart-beta)

v10.6+ で追加された XY Chart。棒グラフと折れ線を同じ図に重ねられるので、売上＋目標線のような表現が得意。

xychart-beta
    title "月別売上"
    x-axis [Jan, Feb, Mar, Apr, May, Jun]
    y-axis "売上 (万円)" 0 --> 100
    bar [30, 45, 60, 55, 80, 95]
    line [30, 45, 60, 55, 80, 95]

折れ線だけ:

xychart-beta
    title "アクセス数推移"
    x-axis [Mon, Tue, Wed, Thu, Fri]
    y-axis "PV" 0 --> 1000
    line [400, 550, 700, 650, 900]
  • bar [...] 棒グラフ / line [...] 折れ線
  • 同じ図に両方並べると重なって描画される
  • xychart-beta horizontal で横棒に
  • y軸の範囲は y-axis "ラベル" 0 --> 100

象限図 (quadrantChart)

2軸マトリクス。重要度 × 緊急度 や 影響度 × 実装コスト のような優先度マッピングに。

quadrantChart
    title 施策の優先度
    x-axis 低コスト --> 高コスト
    y-axis 低インパクト --> 高インパクト
    quadrant-1 即やる
    quadrant-2 計画的に
    quadrant-3 後回し
    quadrant-4 やらない
    施策A: [0.3, 0.8]
    施策B: [0.7, 0.7]
    施策C: [0.2, 0.3]
    施策D: [0.8, 0.2]

レーダーチャート (radar-beta)

v11+ で追加。スキルマップやスペック比較。

radar-beta
    title チームスキル
    axis A["コーディング"], B["設計"], C["レビュー"], D["DevOps"], E["ドキュメント"]
    curve a["メンバー1"]{4, 5, 3, 2, 4}
    curve b["メンバー2"]{3, 3, 4, 5, 3}

Note

xychart-beta / radar-beta は beta 扱い。GitHub の Markdown レンダラはバージョンが古くて未サポートのことがある。表示崩れたら Live Editor で確認するのが速い。

ユーザージャーニー (journey)

UX の議論で「どこで詰まるか」を可視化。スコアは 1-5（5 が最高）。

journey
    title ECサイトの購入体験
    section 商品探索
      検索: 4: User
      商品比較: 3: User
    section 購入
      カート追加: 5: User
      決済入力: 2: User
      購入完了: 4: User
    section 配送
      配送通知受信: 5: User, System
      受け取り: 5: User

要件定義図 (requirementDiagram)

SysML 由来。要件間の依存関係・トレーサビリティ。

requirementDiagram
    requirement auth_req {
        id: 1
        text: ユーザーは認証されなければならない
        risk: high
        verifymethod: test
    }
    functionalRequirement login_req {
        id: 1.1
        text: ログイン画面を提供する
        risk: medium
        verifymethod: demonstration
    }
    element login_ui {
        type: UI
    }
    login_req - satisfies -> auth_req
    login_ui - satisfies -> login_req

ブロック図 (block-beta)

自由配置のシステム構成図。flowchart より柔軟にレイアウトできる。

block-beta
    columns 3
    A["Frontend"] B["API Gateway"] C["Backend"]
    D["CDN"] E["Auth Service"] F["DB"]
    A --> B
    B --> C
    C --> F
    B --> E

アーキテクチャ図 (architecture-beta)

クラウド構成図。GCP / AWS / k8s のアイコンを埋め込める。

architecture-beta
    group api(cloud)[API]

    service db(database)[Database] in api
    service disk1(disk)[Storage] in api
    service disk2(disk)[Storage] in api
    service server(server)[Server] in api

    db:L -- R:server
    disk1:T -- B:server
    disk2:T -- B:db
  • group でグルーピング
  • service xxx(icon)[Label] でサービス配置
  • アイコンは cloud / database / server / disk / internet などビルトイン

ZenUML (zenuml)

シーケンス図の代替記法。プログラム的な書き方でシーケンスを描ける。

zenuml
    title Login Flow
    User -> Browser: クリック
    Browser -> Server.login() {
        DB.query() {
            return user
        }
        return token
    }
    Browser -> User: ログイン完了

通常の sequenceDiagram と比べて、メソッド呼び出しのネスト構造が表現しやすい。

Tips

  • 長くなる前にレイアウト方向を変える — 横長になったら flowchart TB、縦長になったら flowchart LR
  • ラベルに改行を入れる — <br/> で改行できる
  • 絵文字を使ってラベルを目立たせる — ["🐧 Linux"] のように
  • Live Editor で確認してから貼る — https://mermaid.live/edit が一番速い
  • 複雑になりすぎたら分割 — 1つの図に詰め込まず、責務ごとに分ける
